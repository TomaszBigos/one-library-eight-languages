# Go

> Port bez zależności zewnętrznych, po Ruście i C#. Zmiany algorytmiczne (`00_common.md`) były w nim od początku.
> Własne rundy G1–G19 dotyczyły prawie wyłącznie jednego: GC Go nie jest generacyjny i przy każdym cyklu skanuje całą
> stertę, więc liczy się każdy wskaźnik i każda alokacja.

## Droga

Przepisanie wprost: konstytucje pl 3,0 s, mg 3,1 s, a profil pokazał 35–40% CPU w GC (żywa sterta ok. 300 MB, ok.
530 MB/s alokacji, cykl ok. 230 ms CPU). Po G1–G2 Go było w czasie równe Javie (pl 2,03 vs 2,19 s, mg 1,69 vs 1,63 s)
przy 35–40% mniejszym CPU na dokument. Po G3–G16 pl 1,57 s, mg 1,18 s wobec Javy 2,24 / 1,60 s (porównanie
etapów w jednej serii). W macierzy
końcowej ×0,72 czasu Javy, najniższy szczyt RSS (232 MB), start 1,7 s (`../data/language_summary.csv`).

| G5 | interner słów dokumentu z adresowaniem otwartym zamiast `map[string]int` (hasz runtime + alokacja klucza na token) | razem z G1: mapa w tokenizerze mg 380 → 190 ms |

## Przykład: klucz mapy bez kopii (G1)

```go
// KeyBytes to widok bajtów wycinka UTF-16, bez kopii.
func KeyBytes(s JStr) []byte {
	if len(s) == 0 {
		return nil
	}
	return unsafe.Slice((*byte)(unsafe.Pointer(&s[0])), 2*len(s))
}

// Kompilator rozpoznaje m[string(b)] i nie alokuje napisu na czas wyszukiwania:
if w, ok := d.wordsByCategory[string(KeyBytes(ToLowerRoot(category)))]; ok {
	...
}
```

## Przykład: dane bez wskaźników (G2)

```go
type NegativeSelectionAlgorithm struct {
	...
	// detektor i = packed[offs[i]:offs[i+1]]: dwie tablice bez wskaźników zamiast
	// wycinka na detektor (1,5 mln wycinków to była ok. 1/3 pracy skanowania GC)
	packed []uint16
	offs   []int32
}
```

GC nie zagląda do `[]uint16` ani `[]int32`, więc duża stała sterta detektorów przestaje kosztować przy każdym cyklu.

## Przykład: odpowiedź na stosie (G10)

```go
// Przed: answer zwracał wskaźnik do nowej odpowiedzi, która uciekała na stertę raz na słowo.
// Po: odpowiedź jest zmienną wołającego, answer ją wypełnia (go build -gcflags=-m: zostaje na stosie).
var buf PoolAnswer
a := p.answer(kind, input, &buf)
```

## Techniki w skrócie

- Przy GC bez generacji duże dane trzymać jako tablice bez wskaźników (bufory, przesunięcia, indeksy `int32`), a nie
  jako miliony małych obiektów.
- `-gcflags=-m` pokazuje, co ucieka na stertę; odpowiedź przez parametr wskaźnikowy wołającego zamiast zwracanego
  wskaźnika.
- W wyszukiwaniu `m[string(b)]` kompilator nie alokuje napisu (podobnie przy porównaniu `string(b) == s`); po G1
  i internerze mapy przestały być kosztem.
- Strojenie `GOGC` nie zastąpi zmniejszenia sterty: przed G2 nic nie dawało, po G2 pomagało tylko na wolnej maszynie.
- Na Windows `time.Now` ma krok ok. 1 ms; krótkie odcinki mierzyć licznikiem wysokiej rozdzielczości.
